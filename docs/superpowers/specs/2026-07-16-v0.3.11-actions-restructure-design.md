# v0.3.11 — Actions restructure: sidebar navigates, main tab works

Date: 2026-07-16
Status: approved, ready to plan
Depends on: v0.3.10 (`2026-07-16-v0.3.10-design.md`) — inherits `CopyLinkButton`

Split out of the v0.3.10 spec. This is the highest-risk change in the sequence: it adds
a leaf kind to `App.tsx`'s pane tree.

---

## Goal

Actions moves from a single sidebar panel to a sidebar-navigates / tab-works split,
mirroring how PR review already opens as a main tab.

- **Sidebar** keeps the repo picker, favorites, and workflow list. It becomes navigation.
- **Main tab** shows one workflow's runs.
- **Right drawer** inside that tab shows the clicked run's jobs and the selected job's log.

```
SIDEBAR              │  MAIN TAB: ci.yml · owner/repo   │ DRAWER: #482 fix: retry
─────────────────────┼──────────────────────────────────┼────────────────────────
[repo picker  ▾]     │  #482 fix: retry  ✔ main·push ◀  │ ✔ build   1m20s
★ Favorites          │  #481 chore: bump ✖ main·push    │ ✖ test    0m45s  ◀
  ci.yml   ✔         │  #480 feat: api   ✔ dev ·pr      │ ⊘ deploy  skipped
Workflows            │  #479 fix: flake  ⊘ main·push    │ ───────────────────────
  ci.yml       →     │                                  │ > pnpm test
  release.yml  →     │                                  │ FAIL src/api.test.ts
```

## Precedent to follow

`PrReviewLeaf` (`App.tsx:143`) is the model: a pane-tree leaf kind
`{ kind: "prReview", id, repo, number }`, opened by `openPrReviewTab` (`App.tsx:1111`)
which dedupes against existing leaves and creates a tab titled `#123 · owner/repo`.

## Design

### `src/App.tsx`

- New `ActionsLeaf = { kind: "actions"; id: string; repo: string; workflowId: number;
  workflowName: string; focusRunId?: number }`, added to the `PaneLeaf` union with an
  `isActionsLeaf` guard.
- `openActionsTab(repo, workflowId, workflowName, focusRunId?)` mirrors `openPrReviewTab`:
  dedupe on `repo + workflowId`, else create a tab. Title: `{workflowName} · {repo}`.
  When the leaf already exists, focus it and update `focusRunId` in place.
- `focusRunId` preserves today's one-click-from-favorites-to-log. A fav card currently
  has a "Logs" button that jumps straight to the relevant job's log; without this the
  restructure would regress that to "open tab, find run, click it". `RunsView` opens the
  drawer for `focusRunId` on mount and whenever the prop changes.
- **Not persisted across restart** — `migrateTab` drops `actions` roots, matching the
  existing `prReview` rule at `App.tsx:385`.

**Guard audit (not optional).** Every `node.kind === "prReview"` / `isPrReviewLeaf` site
must be evaluated for the new kind. An `actions` leaf has no `cwd`, exactly like
`prReview`, so most sites want `kind !== "pty"` semantics rather than a second explicit
comparison. Known sites at time of writing:

| Line | What it does |
|---|---|
| 196 | split: `cwd` fallback for the new pty leaf |
| 258, 268, 281, 361 | pane-tree walkers returning null for non-pty leaves |
| 385 | `migrateTab` — drops the leaf on restore |
| 1044 | active-leaf guard |
| 1063 | `sourceCwd` resolution |
| 1553, 1555 | tab title + `tabCwd` |
| 1720–1722 | `projectRoot` / `scopedProfile` / `onOpenPrReview` wiring |

Line numbers are pre-change and will drift — grep for `prReview` rather than trusting
them.

### `src/github/ActionsView.tsx` (sidebar, shrinks)

- Keeps: repo picker, favorites, workflow list, the Run ▸ trigger button.
- Loses: the run list, the expanded jobs list, `showLog` / `openLog` / `openRunLog`,
  and the `onOpenPreview` prop.
- Workflow rows call `onOpenActionsTab(repo, wf.id, wf.name)` instead of expanding inline.
- Fav cards: the "Logs" button becomes `onOpenActionsTab(r.repo, r.workflowId,
  r.workflowName, r.id)` — same one-click-to-log outcome as today, now via the tab's
  drawer. The card keeps its status line and its v0.3.10 copy button.

### `src/github/RunsView.tsx` (new, main tab)

- Fetches `list_github_runs` for its `repo` + `workflowId`. Owns the run list, the
  Cancel / Re-run / Re-run failed actions, and the `CopyLinkButton` inherited from
  v0.3.10 (relocated from the sidebar run rows).
- Clicking a run opens the drawer for that run.

### `RunDrawer` (inside `RunsView.tsx`)

- Right-side drawer, resizable via a divider, escape-to-close (reuse
  `useEscapeToClose` from `PrReviewView`).
- Top: the run's jobs via `list_github_jobs`. Auto-selects the failed job if any, else
  the first completed job — the same heuristic today's `openRunLog` uses.
- Below: the selected job's log text, with a per-`jobId` in-memory cache.
- Header carries an "Open in preview" button.

### Backend `src-tauri/src/github/actions.rs`

- `job_log` returns `JobLog { path: String, text: String, truncated: bool }` from its
  single existing fetch. It already holds the full text in memory and already writes
  the cache file at `dirs::cache_dir()/vector/logs/job-{id}.log`; it just returns both
  now. The drawer renders `text`; "Open in preview" passes `path` to the existing pane.
- `job_log_loading` and the `prepare_github_job_log` command are **deleted**. They exist
  solely because the preview pane needed a file path to open instantly on a placeholder;
  a drawer renders its own spinner.
- Log cap: 2 MB. Past that, keep the **tail** (CI failures are at the end) and set
  `truncated: true`; the drawer shows a truncation banner and points at "Open in
  preview" for the full file, which is written uncapped.

**Why "Open in preview" survives:** dropping it would regress search, syntax
highlighting, and pinning on logs — all capabilities the preview pane provides today.
The pane path also already handles oversized files
(`read_file_bytes` → `truncated` → `TooLargePlaceholder`).

## Verification

No test suite (per `CLAUDE.md`). Exercise in a running app (`npm run tauri dev`):

- Click a workflow in the sidebar → tab opens, titled `ci.yml · owner/repo`.
- Click the same workflow again → focuses the existing tab, no duplicate.
- Click a run → drawer opens on the failed job's log.
- A fav card's Logs button → tab opens with that run's drawer already showing.
- "Open in preview" opens the full log in the preview pane.
- A >2 MB log → truncation banner, tail visible, preview shows the full file.
- Restart the app → actions tabs are gone (matching `prReview`).
- **Split an actions tab, and drag it between tabs** — the pane-tree guards are the risk
  area, and a missed guard surfaces here rather than at compile time.

## Risks

Adding a leaf kind to the pane tree is the whole risk. Every `prReview` guard in
`App.tsx` is a place the new kind can be missed, and a missed guard means a crash or a
broken split/drag — not a type error. The guard audit and the split/drag verification
step are the mitigation.
